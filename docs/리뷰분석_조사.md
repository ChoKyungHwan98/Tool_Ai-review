# 스팀 리뷰 분석 툴 — 조사 정리

AI 리뷰데이터 분석 툴을 고치기 전에 조사한 내용과, 팰월드(1623730) 데이터로 확인한 결과를 모았다.
조사 기간: 2026-09-22 ~ 09-24

---

## 1. 결론 세 줄

1. **추천률은 스팀이 공짜로 준다.** AI로 리뷰를 읽어서 다시 계산할 필요가 없는 숫자다. 그런데 예전 대시보드는 이 숫자를 가장 크게, 네 번이나 보여줬다.
2. **분석 툴이 답해야 할 것은 세 가지다.** 유저가 왜 싫어하는지, 누가 싫어하는지, 그 결론을 얼마나 믿을 수 있는지다.
3. **통계에 구멍이 있었다.** 화면이 약속한 정확도가 실제로는 나오지 않았다. 대시보드 설명 문구 하나는 사실과 달랐다.

---

## 2. 시중 스팀 리뷰 분석 도구

모든 상용 도구는 스팀의 같은 공개 API를 읽는다. 차이는 데이터가 아니라 **무엇을 결론 내리느냐**에서 난다.

| 기능 | 하는 도구 |
|---|---|
| 감정·주제·버그 분류 | 대부분 |
| 플레이 시간별 구분 | 거의 없음 (2개) |
| 시간 흐름 추적 | 소수 |
| 표본 설계·오차 계산 | **없음** |
| 기획 프레임워크 적용 | **없음** |

- 표본 설계는 우리 툴에만 있다.
- 여기에 기획 프레임워크와 플레이 시간 구분을 붙이면 시중에 없는 도구가 된다.

## 3. 대가들의 기준

| 출처 | 핵심 | 툴에 적용 |
|---|---|---|
| **닐 게이먼** | 사람들이 뭔가 잘못됐다고 하면 대개 맞다. 어떻게 고치라고 하면 대개 틀린다. | **문제**(믿는다)와 **유저 제안**(참고만)을 따로 뽑는다 |
| **MDA 프레임워크** (GDC) | 개발자는 메커닉부터 보고, 플레이어는 재미부터 느낀다 | 리뷰는 재미 층의 신호다. 경험을 **8가지 재미 유형**으로 분류한다 |
| **카노 모델** | "없으면 화나지만 있어도 칭찬받지 못하는 것"(버그·최적화)과 "있으면 감동인 것"은 다르다 | 불만 수만 세면 게임을 특별하게 만드는 것을 놓친다 |

### MDA 8가지 재미 (툴에서 쓰는 이름)

| 이름 | 뜻 |
|---|---|
| 감각 | 보고 듣는 즐거움 |
| 판타지 | 다른 존재가 되어보는 것 |
| 이야기 | 줄거리와 전개 |
| 도전 | 어려움을 이겨내는 성취 |
| 함께 | 다른 사람과 어울림 |
| 발견 | 탐험과 새로운 것 찾기 |
| 표현 | 나를 드러내고 꾸밈 |
| 몰두 | 시간 가는 줄 모르는 반복 |

## 4. 다른 제품들이 리뷰를 보여주는 방식

| 제품 | 방식 | 가져온 것 |
|---|---|---|
| 아마존 "Customers say" | 맨 위에 한 문단 요약, 아래에 주제 버튼, 누르면 그 리뷰만 나옴 | 요약 문단 + 원문 |
| 애플 앱스토어 (2025) | AI가 100~300자로 요약하고, 좋은 점과 나쁜 점을 균형 있게 씀 | 짧고 균형 있게 |
| 구글 플레이 | "사람들이 말하는 것" 칩, 누르면 해당 리뷰로 이동 | 칩 방식 |
| **Thematic** | **많이 나온 것이 아니라 점수를 많이 움직인 것**을 보여줌 | ⭐ 영향도 |
| Enterpret / Dovetail | 점수 → 주제 → 누가 → 할 일 순서로 보여줌 | 화면 순서 |

### 공통 규칙

1. **숫자 위, 원문 아래.** 숫자만 있으면 믿지 않는다. 원문 한 줄이 붙어야 믿는다.
2. **할 일은 5~7개까지.** 그 이상은 아무도 안 본다.
3. **지표를 쌓지 마라.** 점수판만 있는 화면은 보고서지 도구가 아니다.

### 영향도 (Thematic 방식)

> 이 주제를 말한 리뷰를 빼면 추천률이 몇 %p 바뀌는가

- 많이 나온 불만이 곧 가장 큰 문제는 아니다.
- 추천/비추천 값이 이미 있으므로 AI 비용 없이 계산할 수 있다.
- **한계(실측으로 확인):** 추천률이 95%인 게임은 칭찬 리뷰를 빼도 추천률이 거의 변하지 않는다. 그래서 "좋아한 것"은 영향도가 아니라 **칭찬 수**로 고른다. 영향도는 "깎은 것"에만 쓴다.

## 5. 표본과 오차

| 오차 | 필요 리뷰 수 (전체 10만 건 기준) |
|---|---|
| ±10% | 약 96건 |
| ±5% | 약 383건 |
| ±3% | 약 1,060건 |
| ±1% | 약 8,762건 |

- 오차를 절반으로 줄이려면 표본이 4배 필요하다.
- **95%는 신뢰수준**(몇 번 중 몇 번 맞느냐)이고, **±5%는 오차범위**(얼마나 정확하냐)다. 둘은 다른 값이다.
- 필요한 표본은 전체 크기와 거의 무관하다. 10만 건이든 100만 건이든 ±5%면 약 384건이다. 그래서 "전체의 몇 %를 분석"하는 슬라이더는 틀린 설계다. 조절하는 값은 **오차**이고, 건수·비용·시간은 그 결과로 따라온다.
- 이미 있던 것:
  - Cochran 공식과 유한모집단 보정
  - 비추천 약 100건(기대값) 조건
  - 비용 계산

## 6. 예전 툴 진단 (팰월드 실제 데이터)

| 항목 | 값 |
|---|---|
| 한국어 리뷰 전체 | 24,537건 |
| 수집 | 2,188건 |
| 분석 | 1,330건 |
| 버린 짧은 리뷰 (8자 미만) | 858건 (39%), 이 중 **98.1%가 추천** |

### 찾은 문제

| # | 문제 | 원인 |
|---|---|---|
| ① | "비추천을 일부러 더 수집"이라는 설명이 틀림 | 실제로는 원래 비율대로 모았다. 추천률이 93%로 나온 이유는 짧은 긍정 리뷰 39%를 버렸기 때문이다 |
| ② | ±2%를 약속했지만 실제는 ±2.7% | 표본을 수집 건수 기준으로 계산했는데, 그중 39%가 분석 전에 버려진다 |
| ③ | 불만 분석 오차 ±10.4%가 화면에 없음 | 불만 리뷰가 89건뿐이다. 가장 중요한 결론이 가장 불확실한데 그걸 숨겼다 |
| ④ | 고정 측면 5개(그래픽·게임플레이·스토리·성능·가격) | 어느 게임에나 똑같은 칸이라, 팰·건축·멀티가 전부 "게임플레이"에 뭉개진다 |
| ⑤ | 모아놓고 안 쓰는 플레이 시간 | 아래 표 |

### 플레이 시간별 비추천

| 플레이 시간 | 비추천 비율 | 리뷰 수 |
|---|---|---|
| 0~2시간 | **54.5%** | 11건 (표본 적음) |
| 2~20시간 | 8.0% | 363건 |
| 20~100시간 | 5.5% | 899건 |
| 100시간 이상 | 2.3% | 915건 |

- 초반 2시간 유저의 절반이 비추천을 남긴다. 다만 11건뿐이라 이유는 말할 수 없다. 이 구간만 따로 더 모아야 한다(층화 표본).
- 리뷰 55만 건을 본 연구에서는 200시간 넘게 한 유저가 오히려 부정적으로 돌아서는 "역설"이 나왔다. 팰월드는 반대로, 오래 할수록 만족했다.

## 7. 발전 방향 (세 단계)

| 단계 | 추가할 것 | 기획자가 얻는 답 |
|---|---|---|
| 1. 정확하게 | 게임별 주제 자동 발견, 문제/원인/제안 분리 | "건축이 **왜** 불편한가" |
| 2. 기획 언어로 | 8가지 재미, 카노 분류 | "이 게임은 **몰두**와 **발견**의 재미로 팔린다" |
| 3. 누가·언제 | 플레이 시간 층화, 패치 전후, 한국 vs 글로벌 | "**초반 2시간**에 무엇 때문에 떠나나" |

- 스팀은 2025년 8월부터 리뷰 점수를 언어별로 따로 보여준다. 한국 유저가 보는 점수는 이제 한국어 리뷰로만 계산된다.
- 한국만 유독 낮은 항목이 있다면 현지화나 서버 문제라는 신호다.

## 8. 적용한 것과 실측 결과

### 분석 구조 (v3 분석 + v5 인사이트)

| 단계 | 하는 일 |
|---|---|
| A | 리뷰 150건을 보고 이 게임만의 주제 목록을 만든다 |
| B | 리뷰마다 추천 여부, 재미 종류, 주제별 좋음/나쁨, 한 줄 요약을 뽑는다 (10건씩 묶음) |
| C | 불만 리뷰만 골라 문제 / 원인 / 유저 제안을 뽑는다 |
| D | 요약 한 문단과 할 일 5개를 만든다 (AI 호출 1번) |

짧은 리뷰는 AI를 거치지 않고 추천 여부만 센다.

### 토큰 비용 (팰월드 1,330건)

| | 예전 방식 | 새 방식 |
|---|---|---|
| 비용 | 약 $0.138 | **$0.058** |
| 1건당 | $0.000104 | $0.000044 |
| 토큰 | — | 입력 202,733 · 출력 93,967 |

- AI가 하는 일은 늘었지만 비용은 약 58% 줄었다.
- 이유: 짧은 리뷰를 건너뛰고, 답을 짧은 형식으로 받고, 언급된 주제만 출력하게 했다.
- 출력 토큰은 입력보다 4배 비싸다.

### 팰월드 결과 요약

| 항목 | 결과 |
|---|---|
| 좋아한 것 | 팰 디자인 (칭찬 111건), 건축 (102건), 오픈월드 (36건) |
| 깎은 것 | 저장 −0.74%p, 최적화 −0.43%p, 조작 −0.28%p, 멀티플레이 −0.27%p, 건축 −0.22%p |
| 재미 | 몰두 37%, 감각 33%, 발견 31%, 도전 14% |
| 믿을 수 있는 범위 | 추천률 ±0.9%p, 주제 비율 ±2.7%p, 불만 내용 ±10.4%p |

### 돌려보고 알게 된 것

- **"원인"은 AI가 가끔 추측한다** (예: "게임 엔진 문제"). 그래서 화면에서는 "유저가 본 원인"으로 표시한다.
- **유저 제안에 제안이 아닌 서술이 섞인다.** 요청 말투가 있는 것만 남긴다.
- **작은 모델은 막연한 말을 주제로 만든다** ("재밌다" → 게임플레이). 예시를 넣은 질문지로 "기타"가 30/38 → 6/41로 줄었다.
